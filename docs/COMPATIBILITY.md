# Compatibility with opencode

[← README](../README.md)

ocd targets opencode **2.3.1** (`anomalyco/opencode`, tag `v2.3.1`, commit `c769de8`). It was first ported from
branch `v2` at commit `4617210` (2.0.26). It then caught up with 2.1.4, 2.2.2, 2.2.5, 2.2.7, 2.3.0 and 2.3.1 in batches, listed with
what each one checked in [UPGRADE-2.1.4.md](UPGRADE-2.1.4.md), [UPGRADE-2.2.2.md](UPGRADE-2.2.2.md),
[UPGRADE-2.2.5.md](UPGRADE-2.2.5.md), [UPGRADE-2.2.7.md](UPGRADE-2.2.7.md), [UPGRADE-2.3.0.md](UPGRADE-2.3.0.md) and [UPGRADE-2.3.1.md](UPGRADE-2.3.1.md). Wherever it has to look like opencode,
ocd reports version 2.3.1.

## How it is compared

- **Side by side:** both binaries run the same 263 scenarios, and `scripts/parity.py` diffs their outputs. Results
  are in [PARITY.md](PARITY.md). The scenarios cover:
  - the agent loop, sessions, permissions and forms;
  - the read-only endpoints and 74 error cases;
  - the CLI and plugins;
  - GitHub Copilot, the OpenAI WebSocket transport and the experimental todo list;
  - the 2.2 changes: provider wire, `/goal`, background compaction and tools;
  - Mercurial repositories and the desktop browser attachment;
  - the 2.2.7 changes: `run`, MCP OAuth, Copilot Auto, tools, the API and config;
  - the 2.3.0 changes: freeform tools, subagent reports, the step lifecycle, Code Mode search and `fetch`,
    MCP OAuth refresh, pasted sign-ins and client certificates;
  - the 2.3.1 changes: the automation migrations and automations, `Buffer` and argument crossing in Code Mode,
    shell timeouts, read shapes, readable 500s, reasoning replay, ACP background shells and daemon shells across a restart;
  - the 2.3.1 Code Mode changes: `Buffer`, arguments crossing as copies, plugin renames and nested permission rows;
  - the editor integration (ACP) following subagents and background shells after a turn;
  - the 2.3.1 changes: the API (automation, video and blob routes) and config keys;
  - the 2.3.1 provider and server changes: reasoning replay, the ChatGPT token-sharing catalog, video models in the
    catalog, storage failures answering readable 500s, and the local agent CLI's context check;
  - local model discovery for LM Studio, Ollama and vLLM against mock servers.
- **Model requests:** every request ocd sends to the model is compared too: system prompt, tool definitions,
  headers and prompt-cache markers.
- **Result:** 257 of the 263 scenarios are identical. The other six differ in ways that are expected or harmless:
  - the intended renames;
  - the upstream test build's database file name;
  - two timing races that also vary between runs of upstream (one is the title rename racing a failed step);
  - the order of tool-failure events for calls that fail instantly, which upstream gets from its runtime's scheduler;
  - the order of two directories with the same score in fuzzy file search.

- **Per-crate tests:** each crate has its own test suite, many replaying recorded upstream data.

## Works, with a small difference

| Area | Difference |
|---|---|
| Plugins and AI SDK packages | Upstream runs them inside its Bun-based binary. ocd runs them in a Bun helper process and downloads Bun 1.4.4 the first time one is used (or set `OCD_BUN_PATH`) |
| Built-in AI SDK packages | Upstream bundles `@ai-sdk/cohere`, `@ai-sdk/perplexity`, `@ai-sdk/vercel` and `gitlab-ai-provider`. ocd installs them from npm on first use, at the same versions; if an install fails, the error wording differs |
| `session.http.response` plugin hook | Receives the whole response body as text instead of a stream |
| Plugin worktree strategies | Used only after the project's location has loaded; before that, worktree tools fall back to git |
| Persistent terminals and the process daemon | The same `opencode-pty` helper (0.6.0), downloaded once (sha512 and sha256 pinned per platform) instead of carried inside the binary: on the first terminal, or by the managed service at boot. `OPENCODE_PTY_BIN` overrides it like upstream |
| Mini mode (`ocd mini`) | A port of upstream's mini frontend. In 63 screens compared side by side the text was identical, except one startup race; code blocks are highlighted with syntect instead of tree-sitter, so some TypeScript and JavaScript token colours differ |
| Error texts | A few come from Rust instead of Bun or Node: file-system errors, MCP JSON-schema validation and network errors |
| Client certificate keys | Bun's BoringSSL also presents P-521 ECDSA keys and reads PKCS#8 keys encrypted with PKCS#12's RC2 and RC4 schemes. ocd's TLS stack (rustls with ring) can't sign with P-521, and those legacy schemes aren't read: such a certificate fails every request with `FailedToOpenSocket`, where upstream presents it |
| Start-up events | A new session's start-up notifications arrive about 0.5 s sooner; same events, same order |
| Stopping `ocd run` | On SIGINT/SIGTERM ocd interrupts a background job's session once its input is delivered, with `resume: true` (upstream interrupts when the session starts), so a cancelled job's notice can't hold up the exit. Same output and exit codes |
| Tool failure events | When several tool calls in one response fail instantly (unknown tool, unparseable input), upstream records some of the failures in the middle of the response, where its runtime's scheduler happens to yield; ocd records them after it |
| Automations (2.3.1) | `experimental.automations` (old name `experimental.schedules`, off in releases): timers (`at`, `every`, `cron` in a zone, `expires`), prompt actions to a session or to a new subagent child per run, model-free Code Mode actions with state and one send, the tools, `/automation`, the six routes, pause/resume, the KV lease `automation:leader` and the rewake after a restart, on the same `automation` table, so ocd and 2.3.1 list and run each other's automations. Event triggers are not ported (see below). Plugin activation is part of building a location in ocd, so it does not count toward a code action's 30 s cap |
| `pair --remote` | A native OpenTunnel client (`crates/oc-tunnel`) replaces upstream's JavaScript SDK. It keeps the tunnel in the same place, so ocd, upstream and the opentunnel CLI share a device's tunnel. Tested against a local stand-in for the service, not yet against opentunnel.xyz |

## Not implemented yet

| Feature | Notes |
|---|---|
| TUI plugins (the `tui` entrypoint) | Not planned: they need upstream's SolidJS terminal UI |
| Third-party packages for upstream's model runtime (`@opencode/ai`) | AI SDK packages do work |
| Image previews in the TUI | `session.image_preview` and `prompt.image_preview` (off by default): ocd draws no images in the terminal |
| Speech, video and transcription models | Upstream has these only as library code that nothing in the app calls. From 2.3.1 models.dev video models are kept in the catalog (listed with `GET /api/model?types=video`, never offered for sessions; a video model's ref sent to text, image or decision generation is a 422) and `@opencode/ai/providers/xai/videos` is a bundled package, like upstream; ocd generates no videos |
| Experimental voice and client-hosted MCP endpoints | Listed in the API document like upstream's, but answer 500 `UnknownError` |
| Opt-in features of 2.2.6 and 2.2.7 | Console watches and session warming. Their config keys are accepted and echoed like 2.2.7. `experimental.codemode_vm` is a deprecated, ignored key since 2.3.0 (upstream always runs its bytecode VM; ocd runs its interpreter, tested against it) |
| Automation event triggers (2.3.1) | `{type: "event"}` triggers need MCP Events (`experimental.mcp_events`), which ocd does not port: with that flag off creating one fails like upstream; with it on, every MCP server reads as offering no push events (`MCP server <name> is not connected or offers no events`). Event watches a 2.3.1 process created are left alone: ocd neither opens nor pauses them, and they do not keep its automation lease |
| Opt-in features of 2.3.1 | Video generation (`experimental.video_generate`: both routes answer 403 like a release build, also with the flag on, since ocd has no video protocols) and the full Code Mode (`experimental.full_codemode`). Their config keys are accepted and echoed like 2.3.1 |
| Other experimental features | `location_idle_timeout` and the new designs. Their config keys are accepted and do nothing |

## Different on purpose

| Area | Difference |
|---|---|
| Name | The program name, help text and logo say `ocd` / `opencode-d`. Config, data folders, `OPENCODE_*` variables, the HTTP API and plugin package names keep opencode's names |
| TUI working status line | After you press Enter, a line above the prompt shows what's happening: waiting for the model, thinking, writing, running a tool, retrying or compacting. It also shows a timer ticking every second, the output token count and the interrupt key. A running shell command goes on the row below. Upstream shows only its moving progress bar, which ocd keeps, plus a live "Thinking" row in the transcript, which ocd leaves out while the status line shows it |
| `ocd upgrade` and update checks | Installs from ocd's GitHub releases with checksum verification, and checks once a day instead of every 10 minutes ([details](INSTALL.md#upgrading)) |
| Heap snapshots | The server has no JavaScript heap, so `POST /api/debug/heap-dump` answers `500 UnknownError`. `ocd debug heap-dump --server URL` still captures one from an upstream server |
| Version | `ocd --version` shows ocd's own build next to the compatible opencode version. Clients, plugins and the service see 2.3.0 on the `latest` channel ([details](INSTALL.md#versions)) |
