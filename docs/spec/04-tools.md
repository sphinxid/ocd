## 0. Cross-cutting model

### 0.1 Tool value shape (`schema/src/tool.ts`)

```
Tool.Info = { name, input: ValueSchema, description, execute(input, ctx) -> Effect<Result, Tool.Error>,
              output?: ValueSchema, options?: Options }
Options   = { namespace?: string, permission?: string, codemode?: boolean (default true), pinned?: boolean }
Result    = { output?: <declared output>, content?: string | Content[], metadata?: Record<string, any> }
Content   = { type:"text", text } | { type:"file", uri, mime, name? }
Context   = { sessionID, agent, messageID, id: CallID, progress(metadata) }
Tool.Error (tag "Tool.Error") = { message: string, error?: Defect, metadata?: Record<string,unknown> }
ToolFailure (packages/ai/src/schema/errors.ts:177) = subclass of Tool.Error — what every built-in fails with.
```
(`schema/src/tool.ts:9-102`.)

### 0.2 Names (`core/src/tool/runtime.ts:276-281`, `core/src/tool.ts:304-326`)

- `normalizedName(tool) = tool.name.replace(/[^a-zA-Z0-9_-]/g, "_")`.
- `effectiveName(tool)` = `normalizedName` if no namespace, else `namespace.replaceAll(".", "_") + "_" + normalizedName`.
  e.g. namespace `opencode`, name `models` → `opencode_models`.
- Registration rejected (logged `"Skipping invalid ${kind} registration"`, tool skipped) when:
  - namespace has a segment (split on `.`) not matching `/^[A-Za-z0-9_-]+$/` → `Invalid tool namespace: ${JSON.stringify(name)}`;
  - normalized name not matching `/^[A-Za-z0-9_-]+$/` (only possible when empty) → `Invalid tool name: ${name}`;
  - `codemode === false` and effective name is `execute` → `Tool name "execute" is reserved for CodeMode`;
  - `ToolDefinition.make(definition(tool))` throws → `Invalid tool definition ${id}: ${formatted issue}`.
- Last valid registration for an effective name wins; `update` keeps name/namespace (`core/src/tool.ts:186-201`).

### 0.3 Definition sent to the model (`core/src/tool/runtime.ts:21-27`)

`{ type:"tool", name: effectiveName, description, inputSchema, outputSchema? }`.
Input JSON Schema derivation (`runtime.ts:156-188`):
- Effect Schema → `Schema.toJsonSchemaDocument(schema, {onExcessProperty:"error"})` (so objects get
  `additionalProperties:false`, `optionalKey` fields are omitted from `required`), then:
  1. `flattenAllOf`: `{X, allOf:[{a},{b}]}` merged into the parent when no key collides (recursive);
  2. inline local `$ref: "#/$defs/Name"` (non-recursive refs), sibling keys merged if no collision else `allOf:[target, siblings]`;
  3. drop `$defs` if no local refs remain.
- Empty-struct input → `{type:"object", properties:{}, additionalProperties:false}` (+ description/title etc. if annotated) (`packages/ai/src/tool.ts:243-250`).
- Raw JSON Schema (MCP tools) passes through unchanged; Standard Schema (zod) via its JSON-schema converter, target draft-2020-12.

### 0.4 Input validation error (verbatim, `runtime.ts:88-100`)

```
Invalid arguments for tool "<effectiveName>":
- <path>: <issue message>          (max 5 lines; path "root" if empty; numeric segments as [i], others dotted)
- ...and <n> more issue|issues    (only if >5; "issue" when exactly 6 total)

Arguments provided:
<JSON.stringify(input, null, 2)>

Update the arguments and call the tool again.
```
Issue messages come from Effect `SchemaIssue.makeFormatterStandardSchemaV1()`; replicating Effect's exact
issue text (e.g. `Expected string, got 1`, `Missing key`) is an open question (§14).

Other runtime errors (`runtime.ts:29-61`, `tool.ts:263-284`):
- non-Tool.Error failure from an executor → `Tool.Error{message: err.message | String(err)}`.
- declared output but executor returned none → `Tool did not return its declared output`.
- output fails encoding → `Tool returned an invalid value for its output schema: ${msg}` / `Tool returned a non-JSON value for its output schema: ${msg}`.
- call to tool not in the request's surviving definitions → `Tool is not available for this request: ${name}`.
- unknown tool → `No tool named "${name}" is currently available. Please use a tool from the available tool list.`
- tool choice none (max steps) → `Tools are disabled after the maximum agent steps` (`core/src/session/runner/step.ts:96-97`).

### 0.5 Content normalization (`runtime.ts:261-274`, `tool.ts:73-101,150`)

1. `content` string → `[{type:"text", text}]`; non-empty array → copy; else `[{type:"text", text: stringify(output)}]`
   where stringify = string as-is, else `JSON.stringify(value)` (compact), fallback `String(value)`.
2. After the `tool.execute.after` plugin hook, every `file` part with `mime` starting `image/` and a
   `data:<mime>;base64,<b64>` URI is passed through `Image.normalize` (§11). On decode failure the part is
   dropped and a trailing text part `[N image(s) omitted: could not be decoded.]` is appended; on size failure
   `[N image(s) omitted: could not be resized below the image size limit.]` (exact: ``[${count} image${count === 1 ? "" : "s"} omitted: ${text}]``). Resizer unavailable → passthrough.

### 0.6 Snapshot / which tools are advertised (`core/src/tool.ts:225-288`)

- `whollyDisabled(action)`: the **last** permission rule whose `action` wildcard-matches
  (`options.permission ?? effectiveName`) has `resource === "*"` and `effect === "deny"` → tool hidden.
  (`edit`, `write`, `patch` and `opencode.worktree_remove` use action `edit`.)
- Tools with `options.codemode === false` are **direct** tools. All others go into CodeMode (§13).
- `definitions` = direct tools sorted by effective name (plain `<`/`>` code-unit compare), then the `execute`
  CodeMode tool appended last if `"execute"` is not wholly disabled.
- Session plugin hooks (`context`, `compaction`, `generate`) may then delete or edit definitions
  (patch/edit/write switch §3.4, websearch removal §10, shell description §7, subagent description §12.3).

### 0.8 Permission call shape

Every leaf calls `permission.assert({action, resources[], save[], metadata?, sessionID, agent,
source:{type:"tool", messageID, id}})`. `save` is what an "always" reply persists. User decline is a
*defect* that tunnels through leaf `mapError`s (see `core/src/tool/AGENTS.md:29`); a decline-with-feedback
(`Permission.CorrectedError`) is typed and becomes model-visible text. Ruleset evaluation itself is specified
elsewhere (permission spec). Wildcard: `core/src/util/wildcard.ts:3-14` (`*`→`.*`, `?`→`.`, trailing `" *"`
also matches the bare prefix, `\`→`/`, case-insensitive on win32).

### 0.9 Model-visible error text

A `ToolFailure{message, error}` is shown to the model as `toSessionError(...)`
(`core/src/session/to-session-error.ts:63-68`): if `error` is undefined → `message`; otherwise the **cause is
unwrapped recursively** and the cause's message is shown, unless that message is `""`, in which case the
leaf's `message` is used. Consequence: e.g. `shell` failing with `ToolFailure("Unable to execute command: X",
error: Error("Working directory does not exist: /p"))` shows `Working directory does not exist: /p`.
Effect `TaggedError`s without a `message` getter (e.g. `Environment.NotFound`, `Environment.Failed`) have
empty message → the leaf message is shown. The Rust port must reproduce this unwrap.

### 0.10 External-directory approval (`core/src/file-access.ts`)

`resolvePath(dir, input)` (`file-access.ts:67-77`): Windows-path normalisation (`/c/..`, `/cygdrive/c`, `/mnt/c` →
`C:/`, win32 only), `~` → home, `~/x` → `home/x`, then `path.resolve(location.directory, …)`.

`resolve({path, kind?})` (`:93-123`):
- **internal** if inside `location.directory`, or inside `location.project.directory` (unless that is a filesystem root).
  Internal target: `resource = slash(relative(location.directory, absolute) || ".")` (`\` → `/`).
- else **external**: `resource = slash(absolute)`; boundary `directory` = absolute if kind=`directory`
  (or, with no kind, if `stat` says Directory) else `dirname(absolute)`;
  `externalDirectory = { action:"external_directory", directory, resource: slash(join(directory,"*")),
  save: slash(join(projectRoot(directory) ?? directory, "*")) }` where `projectRoot` = nearest ancestor containing
  `.git` or `.hg` (`core/src/project.ts:49-58`).

`authorizeExternal(targets, ctx, metadata?)`: dedupe external dirs by `resource` (first-seen order); if any,
one `assert({action:"external_directory", resources:[...], save:[...], metadata?})`.

`authorizeRead(file, ctx, {siblingOf}?)` (`:144-161`): resolve (kind `file` only when `siblingOf` given);
if not a same-directory sibling → `authorizeExternal`; then `assert({action:"read", resources:[target.resource], save:["*"]})`.

### 0.11 No stale-read / file-time checks

v2 has **no** read-before-write requirement, no mtime/stale checks, no LSP diagnostics, no snapshots in tools
(see TODOs `core/src/file-mutation.ts:126-134`, `edit.ts:104-107`, `write.ts:41-44`). Mutation serialization only:
`FileMutation.withLock(paths)` — process-wide keyed mutex over the sorted, de-duplicated `FSUtil.resolve`d paths
(`file-mutation.ts:71-74`); per-target write lock + uninterruptible write (`:75-78`).

## 1. `read`

- Registered name `read`; options `{codemode:false}` (`core/src/tool/plugin/read.ts:40-42`).
- Description (verbatim, `read.ts:44`):
  `Read the contents of a file or directory. Supports text files, images, and PDFs. Images and PDFs are presented directly to the model. Each text line is prefixed by its 1-based line number as <line>: <content>. The prefix is for reference and is not part of the file content. Directory entries are returned one per line. Use offset and limit to read large files or directories in sections. Prefer one larger read over many small slices, and use grep to find specific content in large files.`
- Input schema:
```json
{"type":"object","properties":{"path":{"type":"string","description":"File or directory to read"},"offset":{"type":"integer","minimum":0,"description":"The line or directory entry to start reading from (1-based)"},"limit":{"type":"integer","minimum":0,"description":"The maximum number of lines or directory entries to read (defaults to and capped at 2000)"}},"required":["path"],"additionalProperties":false}
```
- Output (structured) = one of `{type:"file", uri, name?, content, encoding:"utf8"|"base64", mime}`,
  `TextPage{type:"text-page", content, mime, offset, truncated, next?}`,
  `ListPage{type:"list-page", entries:[{path, type:"file"|"directory"|"symlink"}], truncated, next?}`.
- Metadata: `{truncated: output.type==="file" ? false : output.truncated}` (so global truncation §2 never re-bounds read output).

### 1.1 Constants (`core/src/tool/read-filesystem.ts:14-21`)
`MAX_READ_LINES=2000`, `MAX_READ_BYTES=50*1024`, `MAX_MEDIA_INGEST_BYTES=20*1024*1024`, `FIRST_CHUNK=256*1024`,
`MAX_LINE_LENGTH=2000`, suffix `... (line truncated to 2000 chars)`,
`MEDIA_MIMES={image/png,image/jpeg,image/gif,image/webp,application/pdf}`.

### 1.2 Algorithm (`read.ts:47-132`, `read-filesystem.ts:116-224`)
1. `authorizeRead(input.path)` (§0.10) → target.
2. `files.read(abs, {offset:0,length:256KiB})`:
   - WrongKind `directory` → list (§1.4). WrongKind other → `PathKindError("a file or directory")`.
3. `Mime.detect(firstBytes)` (`core/src/mime.ts`): PNG `89 50 4E 47 0D 0A 1A 0A`; JPEG `FF D8 FF`; GIF `47 49 46 38`;
   BMP `42 4D`; PDF `25 50 44 46 2D`; WEBP `RIFF....WEBP`; AVIF `....ftypavif|avis`; else text/plain if
   (empty) or (no NUL, valid UTF-8 in streaming mode, control bytes (<9 or 14..31) ≤30%) else octet-stream.
   If in MEDIA_MIMES: size > 20MiB → `MediaIngestLimitError`; else read whole file → `{type:"file", uri:file://…,
   name:basename, content: base64, encoding:"base64", mime}`. (BMP/AVIF fall to text path.)
4. **Unpaged** when `size <= 51200` and neither offset nor limit given: any NUL byte → `BinaryFileError`; else
   `{type:"file", encoding:"utf8", content: TextDecoder(utf-8, BOM-stripping, replacement chars).decode(bytes)
   .split("\n").map(clampLine).join("\n"), mime: mime-types lookup(path) || "application/octet-stream"}`.
   NOTE: `\r` is **not** stripped on this path.
5. **Paged** otherwise (`textPage`, `read-filesystem.ts:291-324`):
   - `offset = page.offset || 1`, `limit = min(page.limit || 2000, 2000)` (0 behaves as unset).
   - Decode bytes, split `\n`; at EOF drop a final empty element, otherwise drop the trailing partial line;
     strip one trailing `\r` from each line.
   - From line `offset`: stop (set `next = lineNo`) when `entries >= limit` or `size >= 51200`; clamp line
     (`clampLine`: if `line.length > 2000` (UTF-16 code units) → first 2000 units + suffix); `lineSize = utf8Bytes +
     (entries>0 ? 1 : 0)`; if `size + lineSize > 51200` → `next = lineNo`, stop; else push.
   - After loop: if `next` unset and `entries >= limit` and more lines exist → `next = offset + entries`.
   - Large files are read in further 256KiB chunks until enough lines (rope index, `:176-223`); result is
     equivalent to selecting lines `[offset, offset+limit)` under the 50 KiB cap.
   - NUL byte anywhere in the bytes consumed up to the last selected line → `BinaryFileError`.
   - No entries and `offset !== 1` → `OffsetOutOfRangeError(offset, totalLines)` where totalLines = newline count
     + (1 if last byte is not `\n`).
   - `TextPage{content: entries.join("\n"), offset, truncated: next!==undefined, next?}`.
6. NotFound → filename recovery (`read.ts:58-80,138-150`): canonicalise basename (NFC, U+00A0/U+202F → space,
   U+2018/U+2019 → `'`); list parent dir; exactly one *file* entry with equal canonical name → authorize that
   sibling (no extra external prompt; separate `read` assert) and read it; displayed path =
   `join(dirname(input.path), basename(alternate))`. Otherwise (or if it's a directory listing) → "missing":
   - suggestions: entries of `dirname(absolute)` whose lowercase contains `basename(input).toLowerCase()` or vice
     versa, first 3 in readdir order, each `join(dirname(input), entry)`.
   - message `File not found: ${input}` or `File not found: ${input}\n\nDid you mean one of these?\n${s.join("\n")}`.
7. AGENTS.md discovery (`read.ts:82-107`), skipped for external targets, failures ignored: walk upward from the
   directory itself (list) or `dirname(file)`, stopping at (and including) `realpath(location.directory)`, collecting
   existing files named `AGENTS.md`; drop those whose directory is the location root or an ancestor of it, and the
   file being read; if any remain → `SessionInstructions.load({sessionID, paths})` (instructions spec).
8. Base64 result with non-media mime → `BinaryFileError` (defensive; unreachable).
9. Errors: BinaryFileError `Cannot read binary file: ${resource}`; MediaIngestLimitError
   `Media exceeds 20971520 byte ingestion limit: ${resource}`; OffsetOutOfRangeError
   ``Offset ${offset} is out of range for this file (${lines} ${lines === 1 ? "line" : "lines"})``; PathKindError
   `Path is not ${expected}: ${resource}` (expected `a file` | `a file or directory`). Any other error →
   `Unable to read ${input.path}` (with cause → §0.9 unwrap). `resource` = §0.10 resource (relative for internal).

### 1.3 Model content (`read.ts:175-211`, verbatim formats)
- Media: `[{type:"text", text: mime==="application/pdf" ? "PDF read successfully" : "Image read successfully"},
  {type:"file", uri:"data:<mime>;base64,<b64>", mime, name: <displayed path>}]`.
- Text (file or text-page): header `Read file ${path}, lines ${start}-${start+n-1}` or `Read file ${path}, 0 lines`;
  then one line per entry `${lineNo}: ${line}`; for text-page with `truncated && next` a final line
  `[Output truncated. Continue reading with offset: ${next}]`; joined with `\n`.
  For `file`: `text = content.replace(/\n$/, "")`, `lines = content === "" ? [] : text.split("\n")`, start=1.
  For `text-page`: `lines = content === "" ? [] : content.split("\n")`, start=`offset`. (Quirk: a page whose only
  selected line is empty renders as `0 lines`.)
- `path` shown is `input.path` as given (or recovered sibling path), not the absolute path.

### 1.4 Directory listing (`read-filesystem.ts:258-289`)
Entries from `readdir(withFileTypes)` (lstat types). Drop `other`. `path = name + (dir ? path.sep : "")`.
Sort: directories first, then everything else; within group `a.path.localeCompare(b.path)` (ICU collation —
see §14). Slice `[offset-1, offset-1+limit)` with same offset/limit defaults; `truncated` if more remain,
`next = offset + selected.length`. Model text: `Read directory ${path}, entries ${start}-${start+n-1}` or
`Read directory ${path}, 0 entries`, then each entry path, then `[Output truncated. Continue reading with offset: ${next}]`
if truncated. Offset beyond end is **not** an error for directories.

## 2. Generic output bounding — `ToolOutput` (`core/src/tool-output.ts`)

- `MAX_LINES = 2000`, `MAX_BYTES = 50*1024`; overridable by config `tool_output.max_lines` / `tool_output.max_bytes`
  (`core/src/config/plugin/tool-output.ts`). Retention 7 days, directory `<data>/tool-output` where
  `<data>` = `$XDG_DATA_HOME/opencode` or `~/.local/share/opencode` (`util/src/global-roots.ts`).
- Applied by the session step runner after every local tool execution (`core/src/session/runner/step.ts:131`).
- Algorithm (`tool-output.ts:67-118`):
  1. If `metadata.truncated !== undefined` → return unchanged (read/grep/glob/shell set it).
  2. `text` = all text parts joined with `\n`. `lines = text.split("\n")`, pop last if text ends with `\n`.
     `totalBytes = utf8(text)`. If `lines.length <= maxLines && totalBytes <= maxBytes` →
     return with `metadata.truncated = false`.
  3. Keep leading lines (≤ maxLines) while cumulative utf8 bytes (+1 per joining newline) ≤ maxBytes.
  4. Write full `text` to `<data>/tool-output/tool_<id>` where id = `Identifier.create(false)`: 12 hex chars
     (`(ms*0x1000 + counter)` low 48 bits, big-endian) + 14 random base62 chars (`schema/src/identifier.ts:16-32`).
  5. Marker: `[showing ${kept>0 ? `lines 1-${kept}` : "0 lines"} of ${lines.length}; full output saved to ${file}]`.
  6. Rebuild content: budget `remaining = kept.join("\n").length` (UTF-16 units); walk parts in order: file parts
     kept; for each text part (subtracting 1 for the separator from the 2nd text part on) keep whole if it fits,
     else keep the prefix that fits (if >0) and insert the marker text part once; after the marker, later text parts
     are dropped (but file parts still kept). If never marked, marker appended at end.
  7. `metadata = {...metadata, truncated:true, outputPath:file}`.
- Hourly cleanup deletes `tool_[0-9a-f]{12}*` files older than 7 days by mtime (`:38-48,129-138`).

### 3.1 `edit` (`core/src/tool/plugin/edit.ts`)
- options `{codemode:false, permission:"edit"}`.
- Description (verbatim, `:125`):
~~~~text
Edit the contents of a file by finding and replacing exact text. When editing text from Read output, preserve the exact indentation (tabs or spaces) and omit the line-number prefix, such as `1: `. Never include the prefix in oldString or newString. The edit fails if oldString is not found. By default, oldString must identify a UNIQUE location. Multiple matches FAIL unless replaceAll is true. Add more surrounding context to disambiguate, or set replaceAll to true to replace every occurrence. Use replaceAll when the change should apply to every occurrence, such as renaming a variable.
~~~~
- Input schema:
```json
{"type":"object","properties":{"path":{"type":"string","description":"File to edit"},"oldString":{"type":"string","description":"Exact text to find and replace"},"newString":{"type":"string","description":"Text to replace oldString with (must differ from oldString)"},"replaceAll":{"type":"boolean","description":"Whether to replace every occurrence of oldString. When false, oldString must match exactly once. Defaults to false."}},"required":["path","oldString","newString"],"additionalProperties":false}
```
- Output `{files: FileDiff[], replacements: number}`; metadata `{files}`;
  content ``Edited ${files[0].file} (${n} replacement${n === 1 ? "" : "s"})`` (file = location-relative resource).
- Algorithm (whole body under `withLock([resolvePath(location.directory, input.path)])`):
  1. `oldString === newString` → `No changes to apply: oldString and newString are identical.`
  2. `oldString === ""` → `oldString must not be empty. Use write to create or overwrite a file.`
  3. `resolve({path, kind:"file"})`; `authorizeExternal`.
  4. Read text (BOM split). NotFound → `File not found: ${input.path}`; directory → `Path is a directory, not a file: ${input.path}`;
     other kind → `Unable to edit ${input.path}`.
  5. `ending = source.includes("\r\n") ? "\r\n" : "\n"`; normalise old/new: `\r\n`→`\n` then `\n`→ending.
  6. Matching strategies, first non-empty wins (`:49-102,163-168`):
     a. **exact**: non-overlapping `indexOf` scan.
     b. **unicode-normalised**: same scan on `normalizeForMatch(source)` vs `normalizeForMatch(old)` (1:1 char
        mapping so offsets are valid): `‘’‚‛`→`'`, `“”„‟`→`"`, `‐‑‒–—―−`→`-`, U+00A0, U+2002–U+200A, U+202F,
        U+205F, U+3000 → space.
     c. **line-trailing-whitespace**: split source into lines (each with start/end, newline flag, contentEnd
        excluding a trailing `\r`); expected = old split on `\n` (drop last empty if old ends with `\n`); a candidate
        at each line index where every `normalizeForMatch(line.trimEnd()) === normalizeForMatch(expected.trimEnd())`;
        if old ended with `\n`, last matched line must have a newline and the match end includes it, else end =
        last line's contentEnd. Overlapping candidates are dropped greedily.
  7. `replacements = matches.length`; apply to first match (or all if `replaceAll===true`) right-to-left.
  8. Preview diff only when `replacements===1` or (`>0` and replaceAll). **Permission assert happens here, before the
     match-count errors**: `{action:"edit", resources:[target.resource], save:["*"], metadata: preview ? {files:[preview]} : undefined}`.
  9. 0 matches → `Could not find oldString in ${input.path}. It must match exactly, including whitespace and indentation.`
     \>1 without replaceAll → `Found ${n} matches for oldString, but expected exactly one. Add more surrounding context to make oldString unique, or set replaceAll to true to replace every occurrence.`
  10. Write `Bom.join(replaced, original.bom || replaced.startsWith("\uFEFF"))`.
  11. Formatter; if it ran, `syncTextBom` and use returned text, else re-read text. Output diff
      `fileDiff(resource, source, finalText)`.

1. `text = stripHeredoc(patchText.trim())` where stripHeredoc matches
   `/^(?:cat\s+)?<<(['"]?)(\w+)\1\s*\n([\s\S]*?)\n\2\s*$/` and takes group 3.
2. Split `\n`, strip one trailing `\r` per line. First line trimmed must equal `*** Begin Patch` else
   BoundaryError first: `The first line of the patch must be '*** Begin Patch'`; last line trimmed must be
   `*** End Patch` (and after begin) else `The last line of the patch must be '*** End Patch'`.
3. Optional `*** Environment ID: <non-empty>` immediately after Begin is skipped.
4. Loop over header lines (trimmed):
   - `*** Add File: <path>` (path trimmed): following lines until a boundary (`*** End Patch`, `*** Add File: `,
     `*** Delete File: `, `*** Update File: ` prefixes on the trimmed line) must start with `+` (untrimmed);
     content = lines with `+` removed, joined `\n`. Else error reason
     `Invalid Add File line for '${path}': expected a line starting with '+', got '${trimmedLine}'`.
   - `*** Delete File: <path>`: next line (if before End) must be a boundary; if it starts with `*** ` →
     generic invalid-header error, else reason `Unexpected line after Delete File '${path}': '${next}'. Delete hunks do not contain body lines`.
   - `*** Update File: <path>`: skip any `*** End of File` lines; optional `*** Move to: <dest>` (empty dest →
     reason `Move destination for '${path}' must not be empty`); then chunks:
     - `@@` or `@@ <ctx>` starts a chunk (changeContext = text after `@@ `); a new `@@` while the previous chunk is
       empty → reason ``Unexpected line found in update hunk: '${line}'. Every line should start with ' ' (context line), '+' (added line), or '-' (removed line)``.
     - lines before any `@@` implicitly open a chunk.
     - `""` → context empty line in both old/new; ` x` → context; `-x` → old only; `+x` → new only.
     - `*** End of File` marks last chunk `endOfFile` (error `Update hunk does not contain any lines` if the chunk is
       empty); after it only blank lines, `@@`, or a boundary are allowed, else reason
       `Expected update hunk to start with a @@ context marker, got: '${line}'`.
     - any other line: reason `Expected update hunk to start with a @@ context marker, got: '${line}'` if chunk
       populated else the "Unexpected line found…" text.
     - no chunks → reason `Update file hunk for path '${path}' is empty`; last chunk empty → `Update hunk does not contain any lines` (when at End Patch) or "Unexpected line found…".
   - anything else → `Invalid hunk at line ${n}: '${line}' is not a valid hunk header. Valid hunk headers: '*** Add File: {path}', '*** Delete File: {path}', '*** Update File: {path}'`.
   Reasoned errors render `Invalid hunk at line ${lineNumber}: ${reason}` (lineNumber 1-based in the stripped text).

empty element. For each chunk in order, starting at `lineIndex=0`:

  trailing empty from new). Still not found: all-blank old → `Failed to find an expected blank line in ${path}` /
  `Failed to find ${n} consecutive blank lines in ${path}`; else ``Failed to find expected lines in ${path}:\n${old.join("\n")}``.
- `seek` tries comparators in order **exact, rstrip (trimEnd), trim, normalized (trim + same unicode map as edit)**;
  for each comparator scans offsets from `start`; with `eof` only offset `lines.length - pattern.length` (must be ≥ start).
- Replacements sorted by start, applied in reverse; ensure trailing `""` (file ends with `\n`); result BOM =
  original BOM || new content BOM. (CRLF files: lines keep `\r`; inserted lines have no `\r`.)

**Tool flow** (`patch.ts:85-290`; all under `withLock` of every path and move path):
1. `patchText` empty → `patchText is required`. Parse error → `patch verification failed: ${error.message}`.
   Zero hunks → `patch rejected: empty patch`.
2. Prepare each hunk in order: `resolve(kind file)`; external targets authorized immediately per hunk with
   metadata `{filepath: absolute, parentDir: externalDirectory.directory}`.
   - add: content = contents + `\n` unless empty or already ends with `\n`.
   - delete: read text; failure → `patch verification failed: Failed to delete ${resource}: ${errorMessage}`.
   - update: base = previously prepared content for the same absolute path (non-move updates chain) or file text
     (`patch verification failed: Failed to read file to update ${absolute}: ${errorMessage}`); derive failure →
     `patch verification failed: ${message}`; move target resolved/authorized.
   - other errors → `Unable to prepare patch at ${hunk.path}`.
   `errorMessage`: NotFound → `file does not exist`; WrongKind → `path is a directory` / `path is ${kind}`; Failed → cause message.
3. One permission assert: `{action:"edit", resources: unique [target and move-target resources], save:["*"],
   metadata:{filepath: all resources joined ", ", diff: patches each + "\n" concatenated, files: patchFiles}}`.
4. Apply sequentially (no rollback): delete → `remove`; move → write dest then remove source; else write.
   Failure messages: `${op}: ${errorMessage}` + (`. Completed before failure: ${resources joined ", "}` if any), with op
   `Failed to delete ${res}` / `Failed to write ${res}` / `Wrote ${dest} but failed to remove ${src}`.

## 6. Ripgrep adapter (`core/src/ripgrep.ts`, `core/src/ripgrep/binary.ts`)

code 2 with stderr containing `regex parse error` or `error parsing regex` (and a pattern) → InvalidPatternError;
code ∉ {0,1,2} → Error(`stderr.trim() || "ripgrep failed with code ${code}"`); code 1 → `[]`; else rows

Args (exact order):
- glob: `--no-config --files [--hidden] [--follow] --glob=<pattern> [--glob=!**/.* unless hidden] --glob=!**/.git/** .`

  extra blank line (the joiner adds another `\n`).

Binary location (`binary.ts`, cached per process):
1. `which("rg")` over `PATH` + `<cache>/bin` (`$XDG_CACHE_HOME/opencode/bin` or `~/.cache/opencode/bin`) — use if a file.

### 7.4 Command scanning for permissions (`core/src/shell/parse.ts`)
Two implementations that are tested for parity:
- **Legacy (default in release builds)**: tree-sitter (web-tree-sitter 0.25.10, tree-sitter-bash 0.25.0,
  tree-sitter-powershell 0.25.10). Parse with the PowerShell grammar if shell name is `powershell`/`pwsh`, else bash.
  For every descendant node of type `command`: parts = children of type `command_name`, `command_name_expr`, `word`,
  `string`, `raw_string`, `concatenation`, plus items of `command_elements` (excluding `command_argument_sep`,
  `redirection`). Name = first token (lowercased for PowerShell). If name ∈ {`cd`,`chdir`,`popd`,`pushd`,
  `push-location`,`set-location`} → directory args (bash: non-`-` args, quotes stripped, skip anything containing
  `$`, `` ` `` or starting `(`, expand `~`/`~/`; PowerShell: `-Path`/`-LiteralPath`-style flag values or positional
  args, expanding `$env:X`, `${env:X}`, `$HOME`, `$PWD` (=cwd), `$PSHOME` (=dirname(shell))). Otherwise push
  `{resource: (parent is redirected_statement ? parent.text : node.text).trim(), save: prefix(tokens).join(" ") + " *"}`.
  Declarations (`export`, `declare`, …) are `declaration_command` nodes in tree-sitter-bash and so produce **no**
  command, but commands nested in their substitutions do. Commands inside `$(...)` are separate commands.
- **Portable** (`core/src/shell/scan.ts`, 2409 lines, hand-written bash/zsh/posix + PowerShell scanner): used when
  config `experimental.portable_shell_scanner` is true, or (unset and) wasm assets are absent or app channel is
  `local`/`dev`. Returns `opaque` (→ error ``Portable shell scanner cannot analyze command: ${reason}``, reasons:
  `command-substitution`, `compound-command`, `dynamic-command-name`, `dynamic-execution`, `heredoc`,
  `invalid-redirect`, `invalid-structure`, `unterminated-escape`, `unterminated-quote`) or commands with
  raw/cooked words; input >64 KiB → opaque `invalid-structure`. Designed to equal the legacy output; the Rust port
  should implement the legacy tree-sitter semantics (tree-sitter crates exist) and treat portable as optional.

## 8. `webfetch` (`core/src/tool/plugin/webfetch.ts`, `core/src/tool/html-markdown.ts`, `core/src/tool/http-body.ts`)
- options `{codemode:false}`. Description (verbatim, `:17-19`):
  `"Fetch content from an HTTP or HTTPS URL and return it as text, markdown, or HTML. Markdown is the default.\n\nUse a more targeted tool when one is available. This tool is read-only. Large text results may be replaced with a preview while the complete output is retained in managed storage."`
- Input schema (note `format` is optional with decode default `"markdown"`; no `default` keyword emitted):
```json
{"type":"object","properties":{"url":{"type":"string","description":"The HTTP or HTTPS URL to fetch content from"},"format":{"type":"string","enum":["text","markdown","html"],"description":"The format to return the content in. Defaults to markdown."},"timeout":{"type":"number","exclusiveMinimum":0,"maximum":120,"description":"Optional timeout in seconds (maximum: 120)"}},"required":["url"],"additionalProperties":false}
```
- Output `{url, contentType, format, output}`; content = `output` string; metadata `{contentType}` (§2 applies).
- Algorithm:
  1. `new URL(url)`; protocol must be `http:`/`https:` else `URL must use http:// or https://`.
  2. assert `{action:"webfetch", resources:[url], save:["*"], metadata: input}`.
  3. GET with headers `User-Agent: Mozilla/5.0 AppleWebKit/537.36 (KHTML, like Gecko); compatible; OpenCode-User/1.0; +https://opencode.ai`,
     `Accept` per format — markdown `text/markdown;q=1.0, text/x-markdown;q=0.9, text/plain;q=0.8, text/html;q=0.7, */*;q=0.1`;
     text `text/plain;q=1.0, text/markdown;q=0.9, text/html;q=0.8, */*;q=0.1`;
     html `text/html;q=1.0, application/xhtml+xml;q=0.9, text/plain;q=0.8, text/markdown;q=0.7, */*;q=0.1`;
     `Accept-Language: en-US,en;q=0.9`. Redirects followed (fetch default). Non-2xx → error. If 403 with header
     `cf-mitigated: challenge` → retry once with `User-Agent: opencode`.
  4. mime = content-type before `;`, trimmed, lowercased. `image/*` except `image/svg+xml`, `image/vnd.fastbidsheet` →
     `Unsupported fetched image content type: ${mime}`. Non-textual (textual = empty, `text/*`, `application/json`,
     `*+json`, `application/xml`, `*+xml`, `application/javascript`, `application/x-javascript`) →
     `Unsupported fetched file content type: ${mime}`.
  5. Body capped at `MAX_RESPONSE_BYTES = 5*1024*1024` (declared Content-Length > cap fails early; streaming overflow
     fails) → `Response too large (exceeds 5242880 byte limit)`.
  6. Steps 3–5 under timeout `input.timeout ?? 30` seconds → `Request timed out`.
  7. Decode UTF-8 (always, ignoring charset). If raw content-type header contains `text/html`: markdown →
     `convertHTMLToMarkdown`; text → `extractTextFromHTML`; html → raw. Else raw content.
  8. Errors → `Unable to fetch ${url}` (+cause → §0.9: cause messages above are what the model sees).
- `extractTextFromHTML` (`:170-187`): htmlparser2; concatenate text nodes not inside `script|style|noscript|iframe|object|embed`
  (depth counter: any open tag inside a skipped element increments), `trim()`.
- `convertHTMLToMarkdown` (`html-markdown.ts`, 658 lines): a streaming htmlparser2 (8.0.2) state machine with byte
  budgets `MAX_MARKDOWN_BYTES = 5 MiB`, content budget `5 MiB - 64 KiB`, nesting cutoff 10 000 (switches to plain
  text fallback). Omitted subtrees: `script style noscript iframe object embed meta link template`, `<head>`,
  elements with `hidden` or `aria-hidden="true"`, closed `<details>` except `<summary>`. Headings `#`×n, blocks
  (`address article aside details dialog div dl fieldset figcaption figure footer form header main nav p section summary`)
  separated by blank lines, `**`/`*`/`~~` for strong|b / em|i / s|strike|del (dropped if empty or spanning blocks),
  links `[text](dest "title")` (dest: escape `\ ( )`, whitespace→`%20`), images `![alt](src "title")`, inline code
  fenced with max-run+1 backticks (padding space when needed), `<pre>` fenced with ``` or ~~~ (length ≥3,
  language from `language-`/`lang-` class), blockquotes `> ` (max depth 8), lists `- `/`N. ` with indentation,
  tables as GFM pipe tables when rectangular and no colspan/rowspan (else rows joined with ` | ` as paragraphs),
  `<dt>` bold, `<dd>` `\n: `, `<br>` → two-space hard break, `<hr>` → `---`. Text escaping: ``\ ` * _ [ ] < > |`` and
  `~` backslash-escaped; leading `#`, `+`, `-` escaped; leading `N.` → `N\.`. Final normalisation collapses
  `[ \t]+\n` (keeping two-space breaks) and 3+ newlines, fixes blank lines between quote levels, `trim()`, cap 5 MiB.
  Generated example (input body, wrapped in `<html><head><title>T</title></head><body>…</body></html>`; the `\n`

## 11. Images (`core/src/image.ts`, `core/src/image/photon.ts`)

## 13. CodeMode (`execute`) — `core/src/codemode/*` and `packages/codemode`

**What it is.** All tools whose `options.codemode !== false` (the `opencode.*` tools, MCP resource tools, MCP server
tools by default, plugin tools by default) are *not* advertised directly. Instead one direct tool named `execute`
runs model-written JavaScript in `@opencode/codemode`, a pure tree-walking interpreter for a JS subset (parsed with
acorn 8.15.0; ~10.8k lines incl. stdlib; no timers/imports/fs/process). Inside the program `tools.<ns>.<name>(input)`
calls registered tools (going through the same `tool.execute.before/after` hooks and leaf permission checks as direct
calls, `core/src/tool.ts:239-245`), `search(...)` (synchronous) discovers tools, and `fetch` (extension `web`,
30 s `AbortSignal.timeout`, returns `{url,status,statusText,ok,redirected,headers:{get,has,entries},text(),json(),bytes()}`,
`core/src/codemode/web.ts`) performs HTTP **without any permission check**. Core passes **no limits** (no timeout,
no max tool calls, no max output). The interpreter itself deserves a separate spec (open question §14).

- Name `execute`; description (newline-joined, `codemode/tool.ts:62-69`):
```

`fetch` is available for HTTP requests. Imports, direct filesystem access, and timers are unavailable; all other external access goes through `tools`.
Within `{ code }`, the only callable tools are those explicitly listed in the Code Mode catalog instructions or returned by the `search` function. Inside `{ code }`, ignore tools shown outside the Code Mode catalog. They are not available in the Code Mode runtime.
Call tools through `tools` using only exact paths and signatures from the catalog. Do not infer or normalize tool names; preserve bracket notation such as `tools.<namespace>["tool-name"](input)`.
Prefer an explicit `return`; if omitted, the final top-level expression becomes the result.
Await every call whose completion matters; pending calls are interrupted when execution ends. Run independent calls concurrently with `Promise.allSettled`.
```
- Input schema: `{"type":"object","properties":{"code":{"type":"string"}},"required":["code"],"additionalProperties":false}`.
- Nested tool result value returned to JS: declared `output` if present, else text parts joined `\n` (or `null` if
  empty). File parts (data URIs) are collected (in call order) and re-emitted.
- Result (`codemode/tool.ts:80-138,310-327`): output text = success: value as string, or `JSON.stringify(value, null, 2)`;
  failure: `error.message` + suggestions not already contained, `\n`-joined and trimmed; then `\n\nWarnings:\n- [kind] msg…`
  (success only) and `\n\nLogs:\n<logs joined \n>` when present. Output `{output, toolCalls:[{tool, status:"running"|"completed"|"error", input?}], error?: true, files:[{data,mime,name?}]}`;
  content = `[{text: output}, ...files as data-URI file parts]`; metadata `{toolCalls, error?: true}`; progress
  updates `{toolCalls}` on every nested call start/settle (fetch calls appear with input `{method, url}`).
  Note an `ok:false` program result is **not** a tool failure.
- Naming inside CodeMode: path = `<namespace>.<normalizedName>` (namespace dots create nesting) or bare name;

## 14. Open questions / porting risks

1. **Effect schema error text** — model-visible validation messages (§0.4) come from Effect's formatter; need a
   table of exact messages (`Expected …, got …`, `Missing key`, `Expected a value greater than 0`, …) per check type.
2. **htmlparser2 fidelity** — `convertHTMLToMarkdown`/`extractTextFromHTML` depend on htmlparser2 8.0.2 tokenizer
   behaviour (implied closes such as `<p>` closed by block openers, `<li>` closing `<li>`, void elements, entity
   decoding incl. legacy entities without `;`, CDATA/comments). No Rust crate matches exactly; likely need a port of
   htmlparser2's Tokenizer + Parser.
3. **`localeCompare`** — directory listing order (§1.4), subagent list, models sort and websearch provider order use
   ICU collation (`localeCompare` with default locale). Decide on an ICU4X collator vs. byte order.
4. **UTF-16 vs UTF-8 lengths** — line clamping (2000), grep text truncation (2000), ToolOutput content slicing and
   CodeMode description truncation use JS string lengths (UTF-16 code units). Must emulate.
5. **Ripgrep result order** is nondeterministic (parallel walker, no `--sort`); replicate as-is or add `--sort path`?
6. **Shell scanner**: confirm which scanner a Rust build should use (legacy tree-sitter grammar versions bash 0.25.0 /
   powershell 0.25.10) and whether to port `scan.ts` (2409 lines) at all.
7. **jsdiff output** — `createTwoFilesPatch`/`diffLines` (jsdiff 8.0.4) hunk construction (context 4 lines) must be
   byte-identical for permission previews and `files` metadata; `similar` crate output differs.
8. **CodeMode interpreter** (`packages/codemode`, ~10.8k lines incl. stdlib) needs its own spec; it defines the JS
   subset, data-copy rules (32 nesting levels), diagnostics, and signature rendering.
9. **Photon resize** — Lanczos3 + PNG/JPEG encoder byte sizes will differ between photon (Rust/wasm) and other image
   crates; photon is itself Rust (`photon-rs`), so use it directly.
10. **`Job.block` backgrounding** (user moves a foreground shell/subagent to background) and synthetic notification
    delivery are specified in the session/job spec, not here.
11. Read tool unpaged path keeps `\r` while paged path strips it — intentional? Reproduce as-is.
12. Formatter `which` cache: enabled commands are cached per `Info` object (WeakMap) for the life of the config
    revision; disabled results are re-probed on every call.
